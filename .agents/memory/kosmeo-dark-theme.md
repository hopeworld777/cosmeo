---
name: Cosmeo dark/light theme system
description: How theming is wired — CSS var architecture, toggle placement, default, and the one page intentionally excluded.
---

- Theme toggling uses Tailwind's `darkMode: ["class"]` (already configured) + a `.dark` block in `src/index.css` overriding the same CSS var names as `:root` (background/card/primary/etc). Any component using semantic tokens (`bg-background`, `bg-card`, `text-foreground`, `border-border`, `bg-muted`, `bg-primary`...) auto-adapts — no per-component dark: variants needed.
- State lives in `src/context/ThemeContext.jsx` (`useTheme()`), persisted to `localStorage["kosmeo_theme"]`. If no stored value exists, falls back to `window.matchMedia("(prefers-color-scheme: dark)")` (not a hardcoded default) — `index.html`'s pre-paint inline script mirrors this exact fallback logic to avoid a flash; keep both in sync if the rule ever changes.
- Toggle UI is `src/components/ThemeToggle.jsx`, mounted in: desktop `DesktopNav` (App.jsx), mobile `HeaderControls.jsx` (shared by Home/Browse/Messages/Wishlist), `Settings.jsx` header, `AuthLayout.jsx` (Login/Register/etc.), and `AdminLogin.jsx`. Add it to new headers the same way if they need it.
- **Reachability gotcha:** with the invite-only waitlist gate on (`PUBLIC_LAUNCH` unset/false), `WaitlistGate` in App.jsx redirects every route back to `/` for non-VIP/ADMIN users — so `WaitlistLanding` is the *only* page a fresh visitor can reach, and any theme bug there blocks manual QA of the rest of the app. Check `waitlistEnabled` state before concluding a toggle elsewhere is broken.
- WaitlistLanding.jsx is **permanently dark-only by requirement** — no `useTheme()`/`isDark`, no `ThemeToggle` import, colors hardcoded to the dark palette. It was previously theme-aware (toggle + `isDark` ternaries) and got explicitly reverted once; if a re-import/merge reintroduces `useTheme`/`ThemeToggle` there, remove it again rather than assuming it's intentional.
- Most `bg-white` → `bg-card` swaps were done across headers/cards app-wide so dark mode isn't just cosmetic on the toggle's own screen. A few `bg-white/NN` instances were deliberately left alone: decorative glass overlays on already-colored/gradient hero banners (AuthLayout, RestrictedScreen, Profile stats banner) and toggle-switch knobs (Sell.jsx) — those aren't theme surfaces.
